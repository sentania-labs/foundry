# Operator rules (example)

Short, numbered, and yours. Foundry reads this before anything else and
holds workers to it. Examples of the kind of rule that belongs here:

1. Lead with the answer, then supporting detail in the order I would act on it.
2. A design question is not a build order. Building starts on an explicit go.
3. Evidence over labels. Verify before a claim enters a record; never guess an identity.
4. Done means seen working: run the artifact, hit the endpoint, view the page.
5. Destructive or outward-facing actions need my verbatim go, recorded first.
6. Never commit a secret or put one in an outward-facing surface.
7. Times are written in my local zone, never UTC or epoch.
